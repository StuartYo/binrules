# BinRules evaluation results

Generated by `npm run report` from `eval/results/final.json`. Do not edit by hand: `tests/results.test.ts` fails if this file and the JSON disagree.

## How to read this

- Both systems use the same model: `nvidia/nemotron-3-super-120b-a12b` (Nemotron 3 Super on Nebius Token Factory), temperature 0.
- **BinRules** rewrites the resident's words, retrieves candidate official entries, asks the model to point at the entry that names the same item, then code checks the pick (two orderings agree, shared words, a separate yes/no check) and reads the bins from the official entry. It declines when a check fails.
- **Model alone** gets the city's list of bin labels with a one-line description each, and is allowed to answer UNSURE. It has no official list and no retrieval. Its answer counts as right if the bin appears anywhere in the official entry's options, which is the most generous reading.
- **Right answer** for BinRules means it cited an entry I accepted for that question. The last column applies the model's looser rule (any bin from the official options) to BinRules too.
- Test questions were frozen before tuning (`eval/FROZEN.json`). Tuning used only the dev split. The test split was run once per configuration; one bug fix forced a second run, listed under History.

## History and disclosures

- **Dev split, final configuration** (nvidia/nemotron-3-super-120b-a12b): official names 100.0% right; messy 93.2% right, 0.0% wrong; not covered 100.0% refused. The only split used for tuning. Final configuration, one run.
- **Test split, first run (before a stop-word bug fix)** (nvidia/nemotron-3-super-120b-a12b): official names 100.0% right; messy 88.2% right, 2.2% wrong; not covered 94.0% refused. The word 'can' was on my stop-word list, so 'Oil can' collapsed to 'Oil' and 'Cans (steel)' lost its head word. I fixed that one bug and re-ran the whole test split. The numbers above are the re-run.
- **Day-one stop-loss check** (before any tuning): nvidia/NVIDIA-Nemotron-3-Nano-30B-A3B alone on all 294 Brisbane official names scored 31.3% right, 26.5% wrong, 42.2% declined (files `eval/results/day1-baseline-*.json`). That is far below the 95% that would have made the project pointless. The headline comparison above uses Super for both systems.
- The out-of-scope labels were checked by hand against the list but not adjudicated with a second person. Broad entries (for example "Household appliances" or "Hats") make some "not covered" labels arguable. BinRules deliberately treats an entry as a match only when it names the item, so class-level questions get "not covered" plus the closest entries.
- The model-alone baseline is allowed to abstain. A plain chatbot that always answers would look worse than the numbers here.
- Re-running the same questions gives slightly different numbers (two runs of the Brisbane test differ by about 2 points), because the hosted model is not bit-for-bit deterministic at temperature 0.
